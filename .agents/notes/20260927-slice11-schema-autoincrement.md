| 场景 | sqlite_sequence 插入前 | 显式 -1 插入后 | 随后默认插入 id |

| sites 空表 | 无行（等效 0） | 行创建，seq 钳到 **0**（非 -1、非 1） | **1**（恰好），次条 2 |

两个非直觉事实（断言口径依赖）：
1. 空 AUTOINCREMENT 表显式插入 -1 时，`sqlite_sequence` 行被创建且值钳到 0，SQLite 不改写负 rowid（-1 原样可读回）。
2. `0024_projection_leases.sql` 的重建迁移（`INSERT INTO __new_* SELECT ... FROM *`，全新库上 0 行）会为 `site_day_usage` / `model_day_usage` / `site_hour_usage` 预建 `sqlite_sequence` 行（seq=0）；`0001_token_management.sql` / `0008_sqlite_schema_backfill.sql` 同理覆盖 `account_tokens` / `route_channels`。全新迁移库的「插入前状态」并非一律无行。

## G1 落点与断言口径

**新文件**：`src/server/db/sqliteAutoincrementSemantic.test.ts`（4 用例；夹具=全量 drizzle 迁移到 :memory:，与 `migrate.test.ts` 同款读取 `drizzle/meta/_journal.json` 的既有模式）：

- `:77` sentinel-only sites：显式 -1 后 `sqlite_sequence.sites` 恰为 0（断言 :95）；首条默认插入 `lastInsertRowid === 1`（断言 :103，**恰好 1，非 ≥1**）；次条 2、seq=2。
- `:116` 非空 sites：seq=2 → 补插 -1 → seq 保持 2 → 下一条默认 3。
- `:137` 同形 token-usage 表 `site_day_usage`：基线 seq=0（钉住 0024 迁移预建行侧效应）→ -1 不抬高 → 首条默认恰为 1。
- `:165` 对照：显式正 id 确实抬高 seq（1 → 10 → 下一个默认 11），保证前三个「保持」断言不空洞。

**为何空表首条默认恰是 1**（不是 ≥1 弱断言）：AUTOINCREMENT 候选值 = max(表内最大 rowid, sqlite_sequence) + 1 = max(-1, 0) + 1 = 1；哨兵 -1 低于序列下限 0，不参与抬高，故新站从 1 起而非 0 或 2。这是 plan §16.2 R2「新建走默认值，得到 ≥1」的收紧版：引物实测给出确定值 1，断言按确定值钉死。

**归属 CI job（二选一定论：主测试 job `test-core`）**：
- `ci.yml:53` `test-core` job；`ci.yml:71-74` Run tests 步骤，`run: npm test` 在 `:74`（带 `DB_PARITY_SKIP_LIVE_SCHEMA: 'true'`，只影响 `.live.test.ts` 的 it.skip，不影响本文件）。
- `package.json` `"test": "vitest run --root ."`；`vitest.config.ts` 仅在默认 exclude 外加 `.worktrees/**`，无 include 收窄、无 live 排除。
- 实测收集：`npx vitest list --root .` 中本文件 4 个用例全部在列（全仓共 3213 个 `.test.ts` 条目被收集），即 `npm test` 实际执行本文件。
- 本文件无环境门控（:memory: + better-sqlite3，均为依赖），test-core 无条件执行。

**变异思路**（哪些实现改动会让断言变红，推理不跑变异）：
1. **DDL 去掉 AUTOINCREMENT**（退化为裸 `INTEGER PRIMARY KEY` rowid 别名）：空表哨兵场景默认插入候选 = MAX(rowid)+1 = -1+1 = **0** → 「首条默认恰为 1」变红；且裸 rowid 表永不产生 `sqlite_sequence` 行 → 「哨兵插入后 seq 恰为 0（行存在且值为 0）」变红。双重变红。
2. **任何让显式 -1 抬高序列的实现**（如哨兵写入前后对 `sqlite_sequence` +1 或写正值）：sites 空表 seq 变 1 → 「seq 保持 0」变红；首条默认变 2 → 「恰为 1」也变红。双重变红。
3. **反向退化**（序列机制完全不更新 `sqlite_sequence`）：前三个「保持」断言会空洞通过——故第 4 用例（显式正 id 抬高 seq）作对照，把序列机制本身钉住。
