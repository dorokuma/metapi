### 修复 diff 摘要（接线实跑暴露的缺陷）

本地实跑矩阵，sqlite `sentinel-only` 用例失败（新建站点 id=0，断言 `>=1` 不满足）。根因：`buildColumnDefinition`（`src/server/db/schemaArtifactGenerator.ts`）对 sqlite 的 `id` 主键列只发 `INTEGER PRIMARY KEY`（裸 rowid 别名），从不发 `AUTOINCREMENT`；而 mysql 发 `INT AUTO_INCREMENT`（`:100`）、postgres 发 `GENERATED BY DEFAULT AS IDENTITY`（`:124`）。哨兵 id=-1 后，裸 rowid 表下一默认插入 = MAX(rowid)+1 = 0。

**修复**（`schemaArtifactGenerator.ts:170-171`，+1 行有效逻辑）：

```ts
const autoincrement = dialect === 'sqlite' && column.primaryKey && columnName === 'id' ? ' AUTOINCREMENT' : '';
return `${quoteIdentifier(dialect, columnName)} ${sqlType}${notNull}${defaultValue}${primaryKey}${autoincrement}`;
```

对齐 mysql/pg 的「`column.primaryKey && columnName === 'id'`」推断式（见 `20260927-slice11-schema-autoincrement.md` G5：硬编码 `=== 'id'` 为既有约定，当前无实害）。

### drizzle 审计结论（id 主键列全数 AUTOINCREMENT，无例外）

修复前对全部 drizzle 迁移做 `id` 主键列审计：**全部 30 条 `id integer` 主键列均为 `INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL`，无例外**（无 `INTEGER PRIMARY KEY` 裸 rowid 变体、无 `id` 列非自增的表）。符合「所有 id 主键表均为 AUTOINCREMENT」的修复前置条件，故安全实施 sqlite 分支统一发 `AUTOINCREMENT`。
